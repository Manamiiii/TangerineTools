# TangerineTools · 系统能力说明

本文档描述当前代码库已经实现的能力范围，以及明确排除在范围外的部分。目的是让任何人（包括未来的开发 session）一眼看清"现在能做什么、还不能做什么"。

## 定位

TangerineTools 是一个**本地优先（local-first）**的个人资料管理 Web App：

- 所有数据保存在浏览器 IndexedDB（通过 Dexie.js 访问），不依赖任何后端服务或云账号。
- 纯静态站点，可直接部署到 GitHub Pages / Cloudflare Pages 等静态托管平台。
- 面向个人使用（Mac / Android 浏览器），不含多用户、鉴权、协作等能力。
- 数据备份/迁移通过手动 JSON 导出/导入完成。

## 技术栈

- Vite + React 19
- Dexie.js 4（`dexie-react-hooks` 的 `useLiveQuery` 做响应式读取）
- lucide-react 图标
- 无 CSS 框架，纯手写 `src/styles.css`
- 无路由库，`App.jsx` 里基于 `window.location.hash` 实现极简路由
- oxlint 做 lint（`npm run lint`）

## 已实现能力

### 1. 场景管理（首页）

- 场景以「行」列表展示（非卡片），每行显示：色点、名称、类型、已启用工具、编辑/删除按钮。
- 支持新建 / 编辑 / 删除场景（弹窗表单）。
- 场景字段：名称、类型（通用整理/游戏资料/镜头素材/资料档案，`constants.js` 的 `SCENE_TYPES`）、色调（`COLOR_PALETTE` 预设色板，新建时优先随机未使用颜色）、启用的工具（`SCENE_TOOLS`）。
- 点击场景行进入该场景的工作台（hash 路由 `#scene/{id}`）。

场景工作台按 `scene.tools` 里启用的、且 `ready: true` 的工具渲染。若启用了多个工具，工作台顶部会出现分段式切换器，可在已启用工具之间自由切换（不会互相影响数据）。目前 `catalog`（资料库）、`owned`（收集记录）、`stock`（统计视图）、`nature`（性格推荐）、`breeding`（孵蛋推荐）、`reader`（阅读伴侣）六个工具均已落地。

### 2. 资料库工具（`catalog`）

在场景工作台内，若场景启用了「资料库」工具，会渲染 `CatalogTool`：

- **资料表（table）管理**：一个场景可以有多个资料表；支持新建 / 重命名 / 删除（仅剩一个表时禁止删除）；顶部有表选择器切换当前查看的表。
- **字段管理**：支持新增、删除、重命名、改类型、拖拽排序、显示/隐藏字段。共 13 种字段类型（`FIELD_TYPES`）：
  - 短文本 / 图文摘要 / 长文本 / 数字 / 图片 / 单选 / 多选 / 布尔 / URL / 日期 / 引用资料 / 多选引用资料 / 指标视图
  - 「图文摘要」的主文字存放在当前字段，可在字段管理中关联同表图片字段和描述字段；表格、详情和编辑表单均按配置组合展示，不依赖业务字段名。
  - 「单选/多选」支持配置选项（文本 + 点击展开的颜色选择 + 可选图标），并可拖拽调整选项顺序。
  - 「引用资料」会在行编辑表单中从指定资料表选择一条记录；「多选引用资料」会选择多条记录。表格/详情中展示被引用行的文本标签；点击标签可打开被引用资料的详情弹窗。
  - 「指标视图」（字段类型仍为 `stats`）是派生视图字段，本身不可编辑，可用条形列表或雷达图展示；通过 `statsDimensions`/`statsMap` 关联任意数量的底层数值字段，支持自动识别（按字段名/key 别名）或手动指定映射。洛克王国预置为生命/物攻/魔攻/物防/魔防/速度六项，并默认使用条形列表。
- **展示配置**：字段的非索引 `display` 元数据可声明紧凑列宽、括号分行、纵向选项、可配置行数的标签、`+x` 溢出提示、摘要单元格、引用头像/标签和图标化单选。资料库与收集记录共用这套渲染协议，场景预置不需要在通用组件中增加字段名判断。新增/编辑行时，选项不超过 5 个的单选使用平铺按钮，较多选项使用下拉框。
- **列头菜单**：每列表头都有「列操作」菜单——编辑、向左插入列、向右插入列、筛选、排序（升/降）、隐藏、删除。
- **筛选面板**：按字段类型提供不同的筛选控件（数字/日期用范围，单选/多选用勾选列表，布尔用二态开关，指标视图暂不支持筛选）。
- **排序**：点击列头可切换升序/降序；洛克王国精灵表默认按「编号 -> X 阶从小到大 -> 最终形态 -> 首领形态」排列；同编号、同形态内，无括号的名称优先于带括号的名称。其他有编号的资料表仍按编号自然升序。
- **分页**：可调页大小（10/20/50/100，默认 20），显示总条数与页码。
- **表格视图（紧凑）**：单元格文本两行截断 + 悬浮提示；操作列固定在右侧、表头固定在顶部，方便横向/纵向滚动时操作。
- **详情视图（宽松）**：点击「查看详情」弹出详情弹窗，展示该行**全部字段**（含被隐藏的底层数值字段，并标注「隐藏列」徽章），提供编辑/删除入口。同编号形态的培养向对比集中在性格推荐工具中展示。
- **搜索**：工具栏内的搜索框对可搜索字段做文本匹配过滤。

### 3. 收集记录工具（`owned`）

场景启用「收集记录」工具后会渲染 `OwnedTool`，用来记录“我和资料库对象之间的收集关系”。它同时覆盖两种模型：

- **一对一**：同一个资料项只保留一条收集记录，适合成就、镜头、素材、角色解锁等“一项只需要完成/收集一次”的内容。
- **一对多**：同一个资料项可以有多条收集记录，适合洛克王国精灵、随机装备、重复卡牌等“一种对象可以拥有多份实例”的内容。

实现约束：

- 数据复用 `catalogTables` / `catalogFields` / `catalogRows` 存储，通过 `catalogTables.kind === 'owned'` 与普通资料库表区分；`collectionMode` 是非索引配置，不引入 Dexie schema 版本变更。
- 普通新建场景首次进入「收集记录」时只创建一张空的收集记录表，不预置任何业务字段；用户可在该工具内打开「字段」自行配置。
- 洛克王国是应用自带的预置场景，首次进入「收集记录」时会补齐精灵收集字段（精灵引用、性格、血脉、外观细分、特长、游戏伙伴标记、性别、备注，以及隐藏的个体异色/是否炫彩兼容字段），这些字段被视为洛克王国场景自身的数据模板，而不是所有场景的默认模板。界面只编辑外观细分，并由它同步维护隐藏的异色/炫彩兼容值；明确的普通外观和无伙伴标记默认保存为“无”，不显示“未选择”。精灵引用按字段配置展示头像和名称；异色与血脉使用 BWiki / patchwiki 图标，炫彩使用游戏界面的多色五角星图标，性别使用经典红蓝符号。
- 洛克王国收集记录工具提供场景专用的扫描录入弹窗，正式视频输入固定为当前手机录制的 3200×1440 横屏 HEVC MP4。视频选择位于首要操作区，录屏方式、六维公式和备用导入使用同规格的默认折叠说明。扫描器约每 0.30 秒观察一次画面，以右侧信息面板的连续稳定度和固定区域清晰锚点挑选终态，并使用左侧精灵列表以及名称与性别、伙伴标记、血脉、等级、特性、六维、性格、特长和外观图标组成的复合变化特征区分连续精灵；相同复合特征只保留一张，截图、固定间隔和当前时间抽帧收在备用排错入口。内置离线 OCR 的首轮识别保留游戏原文；匹配不足 78% 时，对固定裁切生成高对比单行图，并使用资料库和字段选项组成的有限字符表再次识别。性格有限词表只包含性格名称，不包含选项中的属性解释；性格重试使用单行和单词两种版面模式，仍不可靠时保持未识别而不强配。唯一显示名直接关联资料库；多个括号形态共用同一游戏显示名时，扫描器追加读取特性、等级、星级和六维面板。等级使用原图与高对比图的中英文数字识别；等级面板分母固定为 60，因此可恢复斜杠漏识别的 `1360→13/60` 和分母误读的 `1350→13/60`。六维颜色与数字使用同一完整雷达区域，避免截断不同位数的右对齐数字；数字优先比较简体中文与英文模型对原始裁切的读取结果，仅在原图为空或冲突时使用高对比单行和高对比单词补充表决。等级和六维保留全部 OCR 候选，并按候选形态、1–60 级、星级、性格、颜色和天分档位联合筛选；已识别等级作为强证据，只有其他等级的整体公式结果明确胜出时才纠正。合法候选中出现的 OCR 数字可以恢复，类似图标笔画造成的额外前后缀或缺少一个前后缀数字只在能还原合法面板值时参与整体比较，其余异常值保持未识别。至少三项可靠白色雷达数字时优先按未加成项比较；四项数字且至少两项为可靠白色时固定白色项并枚举其余天分；否则要求至少五项完整六维。默认折叠的复核诊断展示实际六维、颜色、等级与数字重试候选、联合约束尝试、公式纠正或拒绝原因、各候选公式误差、领先差值与具体失败原因；缺失公式输入时退回五维形状相关性。自定义昵称也可以由特性和同一公式缩小候选，无法拉开差距时要求手动选择；手动修正性格会自动复用当前帧数据重判形态。逐帧人工核对和显式确认后才创建一对多收集记录；确认后的字段变更会撤销该帧确认状态。名称右侧的性别符号按蓝色 `♂` / 红色 `♀` 在本地保守识别，不清楚时要求手动选择。血脉左侧的伙伴标记使用实际详情页裁取的“无”与九种标记本地模板识别，未检测到有效前景时同样保存为无标记；形状匹配低于 68% 或候选相近时要求人工选择，并展示最佳和次佳模板分数用于复核。9 种已有清晰原始素材的稀有外观使用本地图标模板保守匹配，缺少模板或未达到匹配门槛时要求手动选择。媒体、时间点特征和抽取帧不持久化；扫描器不控制游戏或发送键鼠事件。外观细分同步推导旧 `shiny` / `colorful` 值。
- 扫描复核按同一精灵形态比较当前收集表已有行的外观、性格、性别和特长；四项完整一致，或无冲突且至少三项一致时要求用户明确选择仍然新增或跳过本帧，两项一致且冲突有限时只提示核对。伙伴标记和血脉只作辅助展示，等级、星级与雷达六维不持久化为身份字段。该检查不覆盖、合并或删除已有收集记录；一批画面中尚未决定或确认的帧也不会在保存其他记录时被清除。
- 扫描器可以在用户明确点击后，把当前帧低于 78% 且仍具有足够本地文字相似度的性格、血脉和特长 OCR 结果，以及相似度接近的最多 8 个本地候选发送给已配置模型；精灵身份、空白或证据过弱的文字、伙伴标记、外观、性别和高置信字段不会发送。模型只能返回候选值，结果只填入待复核表单。
- 收集记录支持关键词搜索、按引用和分类字段组合筛选、20/50/100 条分页，以及跨页勾选。批量修改一次只更新一个明确选择的非引用字段；洛克王国限定为性格、血脉、外观细分、特长、游戏伙伴标记或性别，不提供批量删除、自动去重或自动合并。修改外观细分时同步更新兼容的异色与炫彩字段。
- 洛克王国伙伴标记建议由全部收集记录和现有性格/PVE规则即时派生，不写入推荐字段。同编号不同形态共同去重；生命、速度、物防、魔防实际标记作为人工保护直接跳过，其余个体按稀有外观、PVE投入、性格档位、同乘/爱分享覆盖和同组重复关系建议闪电、果实、房屋或无。列表同时显示游戏实际标记和建议标记，并可只查看需要调整的记录。
- 页面内的统计摘要对当前筛选结果按任一引用或分类字段分组计数，筛选命中数与总记录数同时可见。洛克王国预置默认使用这项内嵌统计，不启用独立统计视图。
- 勾选记录后可以运行智能检查：程序先用现有性格规则确定字段问题、最终分档、普通/稀有个体处理方式和残缺魔镜目标；模型仅在用户再次点击后接收最多 50 条精灵名、性格、外观和程序结论，用于整理处理优先级。检查和模型说明都不会自动修改记录。
- 单元格渲染、表单输入复用资料库的 `CellView` / `FieldInput`，视觉风格与资料库一致；可搜索引用字段使用同一个组合框完成展开、输入筛选和选择。
- 一对一模式下，如果存在 reference 字段，新增同一引用对象的记录会更新已有记录，避免重复；一对多模式允许同一引用对象出现多条记录。

### 4. 统计视图工具（`stock`）

场景启用「统计视图」工具后会渲染 `StockTool`。它从当前场景的资料库表与收集记录表中选择数据源，按字段做即时分组统计，并可叠加一个数值阈值条件。

- 数据源：当前场景内的普通资料表（`!table.kind`）与收集记录表（`kind === 'owned'`）。
- 分组：选择任意非指标视图字段；首次打开优先选择单选、多选、布尔等分类字段，多选字段会展开到多个分组。
- 条件：可选择一个数值字段并设置“≥ 阈值”的过滤条件。
- 结果：展示总记录数、命中记录数，以及各分组数量。
- 聚合计算位于 `src/domain/stock.js`，多选字段展开、空值分组和数值阈值均由纯逻辑测试覆盖。
- 导入兼容 `kind === 'stock'` 的历史记录并原样保留；当前统计视图不读取这类固定表。
- 统计视图作为通用场景可选工具保留；洛克王国预置把收集记录分布放在收集记录页面内，因此默认工具列表不包含独立统计视图。用户自定义过的场景工具组合不会被迁移覆盖。

### 5. 性格推荐工具（`nature`）

场景启用「性格推荐」工具后会渲染 `NatureTool`：

- 顶部使用一个可搜索组合框完成精灵展开、输入筛选和选择，再次展开时自动滚动到当前精灵；手动六维输入默认折叠，支持生命、物攻、魔攻、物防、魔防、速度。个体值区允许从六项中任选三项设为 `+10`，公式面板按生命与其余五维各自的最终面板公式、性格强化 `×1.2` 和弱化 `×0.9` 即时显示结果，并提供可展开的基础资质、当前雷达面板、等级、星级、天分和性格倍率说明。扫描录入页复用同一公式说明，并解释未显示天分的枚举边界。
- 洛克王国场景中，资料带入固定绑定「精灵基础资料」表。选择精灵后以紧凑摘要展示名称、形态、六维、该精灵实际具有的特性标签，并通过 `skillRefs` 读取「技能资料」表中的真实技能行；未选择精灵时不展示具体特性标签。
- 精灵选择器每个编号只展示一个末端普通形态入口；标记为 X 阶但位于进化链末端、或后续仅有首领形态的普通精灵同样可作为入口。地区/外观变体和首领形态不重复占用筛选项，但仍各自使用自己的六维、特性与技能独立判断。综合推荐取各形态结果的并集，详情标注候选性格适用的具体形态。六维条形图从 0 起算，以全资料库全部属性的真实最高值为统一满刻度，并标记全局最低有效值；顶部另外给出分位、排名和统计基线。同编号形态对比使用系别图标，在展开全部技能前标出仅某形态拥有的技能，并强调相对入口形态变化的六维数值和分位；对应的普通形态与首领形态按同一外观一行两列展示。
- 性格推荐按“同进化链精灵引用 + 具体性格值”匹配当前场景的收集记录；非最终形态的拥有记录也计入最终形态。拥有状态区分普通、异色和炫彩个体。未获得候选提供预填精灵与性格的快速新增入口。
- 单只精灵定位核对可以引用 B站和小红书的当前版本玩法材料；链接、作者、时间和具体画面位置按外部研究资料规范记录，观察事实与作者观点分开处理。这些材料只参与规则审计，不直接写入 BWiki 正式预置或照搬外部性格结论。
- 评价全部 30 个合法性格候选（6 个可修正维度中，强化一项、弱化另一项；不允许同项增减）。
- 全部候选先按强化维度分组，再按「推荐 / 可保留 / 不推荐」分档；候选行展示性格增益/代价、精确获得状态和评分。多形态精灵的候选行展示各形态评分范围，详情逐形态展示独立评级与分数，不计算跨形态平均分。
- 性格推荐提供单只分析与全局完成度两个视图。全局视图按编号合并形态，统计推荐/可保留性格中的准确成品、稀有个体银镜可修目标和真实缺口；一个稀有个体最多覆盖一个同强化项目标。页面支持按完成、银镜后完成和未完成筛选并直达单只分析。单只候选以绿色“已获得”和红色“未获得”区分拥有状态。
- 最终性格分档之外单独给出捕捉与残缺魔镜建议：同一强化维度存在更高档位目标时显示减益修改目标；普通易刷个体仍按最终性格刷取，异色或炫彩个体在强化方向有效时标记为银镜可修，强化方向无有效路线时标记为仅收藏保留。
- 技能线索、公式辅助和速度线作为固定分析依据放在 PVE 与性格候选之间；速度跨档按相同满速度个体的最终面板比较，基础速度 `65–83` 仅在核心技能组或特性明确需要先手且加速后越过 `84` 中速竞争线时放行。完整技能池中的零散速度/先制技能不构成灰色速度区的核心证据；同一区间也不自动放行减速，只有多项明确后手/负先制收益或慢速强化传递机制才把速度作为低成本牺牲项。形态间技能或速度不同时可展开逐形态依据。所选性格区域展示修正、分行后的重点理由、风险，以及计入所选个体值和当前性格的最终六维，并对核心属性和风险词做重点强调。
- 「PVE 培养投入」按同编号全部有效形态分别给出星级、定位、主属性和性格方向，避免重复展示同义结论或没有新增信息的详细依据。
- 技能分析统计物攻/魔攻/状态技能数量、攻击技能平均威力、物攻/魔攻占比，并读取技能资料中的 `effectTags` 派生效果标签（先手、速度、回复、减伤、能量、强化、控制、应对、轮转等），用于解释速度、耐久、能量与控制相关的性格收益。未决规则问题记录在 `docs/nature/open-issues.md`。
- 当前性格结果提供按需 AI 解释：只发送已经算出的精灵名称、档位、修正方向、理由、风险、六维、技能/速度摘要和残缺魔镜结论；模型只生成通俗说明，不能改变推荐 / 可保留 / 不推荐档位或另行推荐性格，结果不写入资料库。

### 6. 孵蛋推荐工具（`breeding`）

场景启用「孵蛋推荐」工具后会渲染 `BreedingTool`：

- 读取当前「收集记录」里的精灵引用、性别、是否异色、是否炫彩和性格。
- 读取「精灵基础资料」里的 `eggGroups`（蛋组）与 `speciesGroup`（繁育谱系）字段；当前正式资料来自版本化 BWiki 发布流程。`npm run sync:breeding` 生成 staging，发布流程将繁育字段合入正式精灵行。
- 运行时直接读取精灵预置中的繁育字段；三方合并会补齐或更新明确的正式字段，同时保留用户非空自定义值。
- 父方从异色公个体中选择；母方允许使用普通或异色个体。一次推荐 10 条不重复收集记录，组成 5 对一公一母且至少共享一个可孵蛋组的父母。
- 推荐优先级依次为“母方对应种类尚未拥有异色 > 只有异色母、尚缺异色公 > 任一父母性格命中对应精灵的推荐性格 > 异色父母数量更多 > 炫彩父母数量更多 > 收集记录顺序更靠前”，规则区直接展示该排序口径。
- 后代种类按母亲提示并明确展示精灵名称；性格继承按父/母/随机概率说明展示。父母名称是卡片主信息，头像、性别、异色和炫彩图标作为辅助信息；点击父母打开对应收集记录详情，其中精灵引用可继续打开完整资料详情。
- 洛克王国收集记录表只预置字段结构，不预置精灵收集行；孵蛋推荐直接读取用户维护的真实收集记录。

### 7. 阅读伴侣工具（`reader`）

场景启用「阅读伴侣」工具后会渲染 `ReaderTool`：

- 运行时从 `public/presets/reading-companion/catalog.json` 读取版本化书籍目录，并对资料包 schema、稳定章节、事实风险和引用关系做校验。
- 进入阅读场景后先显示书架；选择一本书后进入该版本独立的阅读空间，并可返回书架切换书籍。书架卡片只展示封面、书名、版本与阅读入口，内置或个人来源使用角落小标记，不展示内部资料准备数量。书内固定提供“阅读输入 / 已遇到 / 地图 / 设置”四个任务 Tab；当前进度存在已解锁无剧透背景或正式事实时增加“背景资料”，并显示当前可查看数量。章节选择位于书籍页右上角，阅读输入可在扫描后直接记录未收录名称，无需切换任务；地图拥有整栏宽度。
- 书架可以根据书名、作者、版本信息和章节数或逐行目录创建个人书籍，并可使用五种内置配色文字封面或上传不超过 1.5 MB 的本机图片。添加书籍时可以选择书籍详情或版权信息截图：Tesseract.js 先在设备端提取文字并保留字段行边界，反复清理中文字符之间的 OCR 空格；关键字段缺失或标签异常时，使用只加载简体中文语言数据的整页书目 OCR 模式重试，避免中文姓名被中英混合识别误判成拉丁字母，并选择结构更完整的结果。确定性解析器优先读取“书名 / 作品名称 / 图书名称 / 标题、作者 / 著者、译者 / 翻译、出版社 / 出版方 / 版权方”等 `字段名：字段值` 行；OCR 自身没有保留换行时，解析器仍可从连续字段标签之间恢复值。作者前、出版社前的未知短标签行可以按固定字段顺序恢复为低置信书名和译者，例如 `FE`、`BE`，但不会被当作可靠文本。当前模型已完整配置时，同一次明确操作还会把 OCR 原文、本机候选和低置信字段发送给该模型；模型可以使用公开书目知识，结合准确 ISBN、出版社、出版日期和相邻字段校对书名、作者与译者。明确识别的书名和译者不会被模型噪声覆盖；低置信字段允许由模型纠正。界面在最终作者或译者与本机候选不同时标记“模型校对”。用户必须核对表单后再创建，截图和 OCR 文字不持久化。个人资料包和封面保存在 Dexie `meta` 表的独立命名空间，不改变 schema v1。个人书籍默认在创建后调用已配置模型准备最多 50 个无剧透人物、地点、概念和事件名称，自动保存为隐藏精确匹配词典，不要求未读用户逐条审核；名称只有以后在当前原文中精确出现时才显示。模型失败不影响创建，阅读页可以随时重试或补充；该词典不生成关系、剧情、章节、解释、坐标或正式事实。书架明确区分“个人书籍”和“内置书籍 · 不可删除”；个人书籍可经明确确认删除，删除时一并清理其所有场景的进度、已遇到名称和个人地图位置。
- 应用初始化会创建稳定 id 为 `scene-reading-companion` 的「经典文学阅读」场景，默认只启用 `reader`。播种标记防止用户删除后被自动重建，已有同 id 场景的名称、工具和其他自定义值不会被覆盖。
- 内置《飘》长江文艺出版社 2018 年 5 月版（ISBN `9787570202188`）的版本元数据和连续 1–63 章稳定标识。资料包中的章节实体和事实集合只接受经过来源及版本边界审计的内容，当前为空；另有 18 个按需精确匹配实体，包括 4 个详情页简介已确认短名的作品人物、林肯、11 个地点或区域名称、“种植园”概念和“南北战争”事件。美国南方只标记为范围随历史语境变化的模糊区域，不提供中心点或固定历史边界，人口普查局 South Region 只作为现代统计参照；三所现实大学使用清楚标注的现代校园代表点；虚构的费耶特维尔女子学院使用现实学校原型参考点，不伪装成虚构地点精确坐标。佐治亚州、美国南方、克莱顿县、亚特兰大、琼斯伯勒、三所大学、费耶特维尔女子学院、“种植园”“林肯”和“南北战争”共 12 个名称带有批准来源支持的简短离线无剧透背景，不预置作品关系、情节解释或历史评价。只有读者输入并确认同名内容后才解锁这些安全名称、空间字段或背景注释。staging 中的 30 个章节实体候选和 2 条事实候选不会直接出现在运行时。

- 项目样式仍按全局约定集中在 `src/styles.css`，阅读伴侣专用选择器统一使用 `reader-` 前缀，避免引入第二套样式入口。
- 研究资料位于 `scripts/reading-companion/data/staging/`；管线自动发现全部 staging，逐书生成版本化 preview，并派生统一运行时 catalog。新书 staging 携带完整 `package`，已有书可用 `basePackagePath` 复用正式包，不需要修改脚本。`check:reader:preset` 输出 dry-run 报告，`apply:reader:preset` 仅在显式确认环境变量存在时写入正式资料包。只有 `approved` 来源进入运行时包；资料源、实体和事实候选均保留在审计数据中，候选必须记录引用来源与阻塞项，且不会被隐式发布。来源可以是中文或其他语言；中文出版社、图书馆、大学、博物馆、政府机构和可靠学术页面按相同直接证据标准审核，转述页面不替代一手资料或指定中文版本的章节证据。
- Codex 或其他模型在开发期间凭公开资料或模型内部知识生成的研究结果属于建库候选，不是运行时模型能力，也不能单独充当来源、指定译本证据或章节剧透边界；测试夹具也不是正式资料。只有仓库内可重复执行的代码、校验、发布流程和已批准资料包属于当前系统能力。
- 阅读伴侣与洛克王国分别维护供应商连接配置；洛克王国扫描、收集检查和性格解释共用洛克域配置。两侧可以把对方当前配置复制为一次性快照，保存后互不联动。每个域、每个供应商的接口地址和模型 ID 保存在 `localStorage`，API Key 保存在独立的 `sessionStorage` 项中。共享层只负责供应商目录、连接、超时、JSON 解析和临时缓存；各工具使用独立的受限提示词、输入范围和输出校验。

### 8. 洛克王国预置资料

- 首次启动自动播种（`ensureSeeded`，通过 `meta.seededRockKingdom` 防止重复播种）：
  - 场景「洛克王国」默认按资料库、性格推荐、收集记录、孵蛋推荐的工作流顺序启用四个工具；收集分布在收集记录页面内统计。
  - 普通资料表包括「精灵基础资料」和「技能资料」。
  - 精灵基础资料包含官方基础资料、六维、图文摘要特性、精灵果实（界面标为「种子」）、精灵蛋、`traitTags`、`skillTags`、`skillRefs`，并维护 `eggGroups`、`speciesGroup`。
  - 技能资料包含技能图标、名称、系别、类型、威力、能耗、先制/速度、效果标签、效果、`learnerRefs`。
- 正式数据由版本化 BWiki staging / preview 经显式覆盖命令发布：
  - `public/presets/rockKingdomRows.json` 包含 592 条精灵 / 形态资料。
  - `public/presets/rockKingdomSkillRows.json` 包含 553 条技能资料。
  - `public/presets/rockKingdomPresetMigration.json` 保存基线正式值 SHA-256，供浏览器做安全三方合并，不含用户数据。
- 精灵与技能图片使用经审计的 BWiki / patchwiki URL；存在异色的精灵保存 BWiki 实际异色图片，收集记录和孵蛋推荐中的已拥有个体按异色状态切换头像。炫彩仍只作为个体标记和繁育概率参与展示，不生成或模拟每只精灵不同的炫彩外观。
- 迁移策略：通过版本化基线正式值指纹做三方合并，只更新空值、无效值或匹配基线正式值的精灵 / 技能字段；用户自定义非空值、用户新增的非占位资料行、owned 收集记录和 stock 统计配置不会被覆盖或删除；不改变 Dexie schema 版本。

### 9. 全量数据导出 / 导入（仅首页）

- **导出**：一键导出全部 Dexie 数据（`scenes` / `catalogTables` / `catalogFields` / `catalogRows` / `meta`）为带时间戳的 JSON 文件下载。
- **导入**：选择 JSON 文件后二次确认，采用「同 id 覆盖、文件中不存在的本地数据保留」的合并策略（非整表替换）；导入前做基础结构校验（`validateImportPayload`）。


### 10. Android Chrome PWA 安装基础能力

- 站点提供 Web App Manifest、`theme-color`、192/512 SVG 图标和 `display: standalone` 配置。
- Manifest 的 `start_url`、`scope` 和图标路径使用相对路径，配合 Vite `base: './'` 兼容 GitHub Pages 仓库子路径部署。
- 提供一个极简 service worker 用于满足 Android Chrome 安装条件；它在安装/激活后接管页面，HTTPS 生产环境采用导航网络优先、同源静态资源缓存优先策略，并在版本升级时删除旧静态缓存。它不缓存版本化预置资料、跨域地图或模型请求，也不读写 IndexedDB。

## 明确排除在范围外的能力

以下能力经过评估后**明确不在当前范围内**，不是遗漏或缺陷：

- **洛克王国对局向深度功能**：BWiki 技能资料用于资料查看和性格推荐输入，不提供完整对战模拟、技能组合求解、属性克制、PVP 环境或配队工具。
- 无人工触发的 AI 自动打标签、模型自动改写正式资料、云同步/多用户协作、后端服务：均超出“个人本地资料管理工具”的定位，未纳入规划。
