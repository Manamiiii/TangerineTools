# 洛克王国世界精灵扫描录入

## 定位

精灵扫描录入是洛克王国世界「收集记录」中的场景专用入口。用户界面直接使用精灵、性格、血脉、特长和外观等游戏语义；帧提取、比例裁切、OCR 和候选匹配由独立模块承担，后续有明确的第二个扫描场景时可以复用这些底层能力。

扫描器只读取用户主动选择的本地截图或视频。它不控制游戏、不发送键鼠事件、不读取游戏进程，也不使用连点、宏或脚本切换精灵。

## 固定手机采集

正式视频输入固定为当前手机录制的 2400 × 1080 横屏 HEVC MP4：

1. 录屏设置使用 2400 × 1080、16 Mbps、24 fps、无声音，并关闭屏幕触摸和导航键点击提示。
2. 在游戏精灵总览页开始录制，手动逐只切换精灵，每只停留约 1.5～2 秒。
3. 原始 MP4 不经过聊天软件压缩或视频剪辑转码，直接在收集记录中打开「扫描录入」并选择。
4. 使用「智能提取稳定画面」，再批量 OCR、逐条核对并点击「确认当前记录」后写入。任何后续字段修改都会撤销该帧的确认状态。

截图、固定间隔抽帧和视频当前位置截图保留在「备用导入与排错」中，不属于日常全量录入路径。

视频、截图、抽取帧和 OCR 文本只存在于当前页面内存中；原始媒体和抽取帧不写入 IndexedDB。关闭扫描弹窗后页面释放对应的本地对象 URL。模型纠错是明确触发的可选步骤，只发送当前帧的低置信 OCR 文字和有限候选，不发送图片或视频。

## 回归素材

`test-data/rock-kingdom-scanner/phone-overview-hevc-2400x1080.mp4` 是固定设备的 2400 × 1080、H.265 / HEVC 总览录屏，用于人工验证视频解码、终态筛选、去重、裁切、中文 OCR 和图标匹配。该文件不位于 `public`，不会进入 Vite 生产构建；验证时从扫描器的文件选择框直接导入。

## 采集字段

扫描器关注：

- 精灵名称，对应收集记录的精灵引用；
- 性格；
- 第二层系别区域显示的血脉；
- 血脉左侧显示的游戏伙伴标记；
- 特长；
- 性别，本地颜色识别后由用户复核；
- 外观细分，本地图标识别后由用户复核。

雷达图、六维、等级、捕捉精灵球、携带徽章和第一层精灵系别不采集。

伙伴标记保存游戏中的实际状态，选项为无、果实、闪电、房屋、生命、物攻、魔攻、物防、魔防和速度。九种标记使用本地轮廓模板保守识别；空区域识别为无标记，低分或候选过近时保持人工选择。

外观字段包含“无”和以下 11 种稀有状态：

- 异色；
- 炫彩、异色炫彩；
- 黑白炫彩、黑白异色炫彩；
- S1 炫彩、S1 异色炫彩；
- S2 炫彩、S2 异色炫彩；
- S3 炫彩、S3 异色炫彩。

污染通过血脉文字区分，不属于外观枚举；未确认存在的“异色污染”不进入选项。

扫描器保存 `appearance` 细分值，并同步推导既有 `shiny` / `colorful` 字段。异色炫彩类同时写入两个旧标志，纯炫彩类只写入 `colorful`，异色只写入 `shiny`。界面只编辑外观细分，明确的普通外观默认为“无”；两个兼容字段保持隐藏，仍供性格推荐、孵蛋推荐和旧备份读取。

## 识别与复核

正式视频在识别前校验为固定设备的 2400 × 1080 横屏画面。裁切仍使用该画面内的相对比例，便于浏览器按视频自然尺寸绘制。智能提取约每 0.45 秒读取一次缩小后的右侧面板，不保存这些检测画面；连续画面差异足够小，并且名称、血脉、雷达数值、性格和特长区域具有终态文字的清晰边缘时，才从稳定段选择锚点质量最高的一帧。候选帧与上一张相同时跳过，切换动画、渐变中间态和点击失败后返回原精灵的画面不进入日常复核列表。

OCR 复用应用自带的简体中文离线模型。识别结果与资料库精灵名称、性格选项、血脉选项和特长选项做容错匹配。OCR 与匹配结果都是候选，不直接绕过复核：

- 精灵名称匹配成功的帧才允许写入；
- 性别使用名称右侧蓝色 `♂` / 红色 `♀` 的颜色证据识别；证据不足或红蓝接近时保持空值；
- 伙伴标记与外观模板都设置最低分和领先差值，未达到门槛时保持人工选择；
- 异色、炫彩、异色炫彩、黑白炫彩、S1 炫彩、S1 异色炫彩、S2 炫彩、S2 异色炫彩和 S3 炫彩使用原始游戏截图模板做本地图标匹配；
- 黑白异色炫彩和 S3 异色炫彩没有清晰模板，只能手动选择；本地匹配未达到分数与领先差值门槛时同样不自动填写；
- 低清二次生成图只用于沟通编号，不作为识别素材。

名称、性格、血脉或特长未匹配，或者本地匹配度低于 78% 时，可以点击「AI 纠错低置信字段」。每个字段只向模型提供 OCR 文字和本地排序后的最多 16 个合法候选；模型返回值不在候选范围内时直接丢弃。AI 结果只回填当前待复核帧，不会直接写入收集记录，高置信字段不会发送。

只有具备有效精灵引用且经过显式确认的帧可以写入；确认后再次修改字段会要求重新确认。每个确认帧创建一条新的收集记录，符合洛克王国一对多的个体记录模型。扫描不会覆盖或删除现有记录。

## 伙伴标记建议

收集记录保存 `partnerMark` 作为游戏实际标记，未打标明确保存为“无”，不使用空值代替；建议标记由当前全部收集记录、正式精灵/技能资料和性格规则即时派生，不写回行值。新增、编辑或扫描写入记录后，同编号全部形态组成的比较组会重新计算，列表提示实际标记是否需要调整。

- 生命、速度、物防和魔防是人工控制的保护标记。扫描到任意一种时保持原样、跳过判断，但该个体仍参与相同性格和关键特长的覆盖统计。
- 稀有外观至少保留：性格适合高投入 PVE 时建议闪电；否则性格为推荐或可保留时建议果实；其余建议房屋。
- 闪电只用于 PVE 评级为优先培养或适合培养、且当前性格属于该 PVE 培养方向的个体。普通外观还必须属于一、二代御三家谱系：喵喵、火花、水蓝蓝、松仔、小勇狮或水滴蛇；其他精灵必须是异色、炫彩或异色炫彩类外观。
- 普通外观只为推荐或可保留性格保留一只；同编号不同形态共同去重。受保护或稀有个体已经覆盖该性格时不再保留普通重复个体。同性格优先关键特长，其次其他特长，再其次无特长；仍相同时优先沿用已有实际标记和较早记录。
- 普通外观的可用性格始终优先使用果实。性格不合适的同乘、爱分享可以各额外保留一只并建议房屋，但同组保留个体已经覆盖对应特长时不再增加。
- 物攻和魔攻保留为人工备用标记，当前规则不主动推荐。

列表同时展示实际标记字段和派生的建议标记，提供“仅看需调整”。受保护标记显示为人工保护且永远不报错；其余标记不一致时显示确定性原因。
